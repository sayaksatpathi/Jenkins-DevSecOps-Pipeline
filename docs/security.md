# Security Policy

## Credentials Management

### Jenkins Credentials Store

All secrets are stored in the Jenkins Credentials Store (encrypted at rest).
**No secrets appear in:**
- `Jenkinsfile`
- Shell scripts committed to Git
- `Dockerfile`
- `README.md` or any documentation
- Environment variable defaults in source code

Credentials are injected at runtime via:
- `credentials()` binding in the `environment` block
- `withCredentials([...])` step for stage-scoped secrets
- `sshUserPrivateKey` binding for SSH deployment keys

Jenkins automatically masks credential values in console output.

### Required Credentials

| Credential ID          | Type                       | Used in stage   |
|------------------------|----------------------------|-----------------|
| `ecr-registry`         | Secret text                | Push to ECR, Deploy |
| `aws-access-key-id`    | Secret text                | Push to ECR, Deploy |
| `aws-secret-access-key`| Secret text                | Push to ECR, Deploy |
| `deploy-host`          | Secret text                | Deploy, Verify  |
| `deploy-ssh-key`       | SSH Username with key      | Deploy          |
| `cosign-private-key`   | Secret file                | Sign Image      |
| `cosign-password`      | Secret text                | Sign Image      |

## AWS Authentication

Jenkins uses IAM credentials with the minimum required permissions (see `iam/jenkins-iam-policy.json`).

**Permissions granted:**
- `ecr:GetAuthorizationToken`
- `ecr:BatchCheckLayerAvailability`
- `ecr:GetDownloadUrlForLayer`
- `ecr:BatchGetImage`
- `ecr:PutImage`
- `ecr:InitiateLayerUpload`
- `ecr:UploadLayerPart`
- `ecr:CompleteLayerUpload`
- `ecr:DescribeImages`
- `ecr:DescribeRepositories`

**Not granted:**
- `AdministratorAccess`
- `IAMFullAccess`
- EC2 management
- S3 access
- Any other AWS service

---

## GitHub Webhook Authentication

Webhook payloads from GitHub are signed with an HMAC-SHA256 signature using a shared secret.

The signature appears in the `X-Hub-Signature-256` HTTP header.

Jenkins (via the GitHub Integration Plugin) validates this signature before processing.

**Never expose the webhook secret in:**
- Logs
- Documentation  
- Source code
- Chat or email

## Container Security

### Image Build
- Multi-stage Dockerfile minimizes attack surface
- No development tools in the final runtime image
- Non-root user (UID 1001) for all container processes
- Pinned base image (`python:3.12-slim`)
- Pinned application dependencies (`requirements.txt`)

### Image Scanning (Trivy)
- Every image is scanned before deployment
- CRITICAL unfixed vulnerabilities block deployment
- JSON report archived in Jenkins as build artifact
- Reports retained for audit trail

### Software Bill of Materials (SBOM)
- Generated by Syft for every built image
- Two formats: CycloneDX JSON and SPDX JSON
- Archived in Jenkins as build artifacts
- Enables incident response: "which of our deployed images contain libX?"

### Image Signing (Cosign)
- Every image is signed before pushing to ECR
- Signature is stored as an OCI artifact alongside the image
- Verification is performed immediately after signing (within the same stage)
- Private key stored as Jenkins Secret file, never on disk or in Git
- Public key (`cosign.pub`) can be committed to the repository for external verification

```bash
# Verify a deployed image using the public key
cosign verify --key cosign.pub <ECR_REGISTRY>/jenkinsforge:<tag>
```

## Pipeline Trust Boundary

```
GitHub (source of truth)
    │
    │  webhook — HMAC-SHA256 signed
    ▼
Jenkins (trust boundary)
    │
    │  pipeline executes in an isolated workspace
    │  credentials never written to disk unencrypted
    │  Docker containers have --user root only for pip install
    │  deploy containers use app user (UID 1001)
    ▼
ECR (immutable image registry)
    │
    ▼
EC2 Deploy Host (isolated from Jenkins — SSH only)
```

## Failure Gate Policy

The pipeline **fails closed**: any stage failure prevents deployment.

| Stage            | Failure blocks deployment? |
|------------------|---------------------------|
| Unit Test        | Yes                       |
| Lint             | Yes                       |
| SAST             | Yes                       |
| Dependency Scan  | Yes                       |
| Docker Build     | Yes                       |
| Trivy (CRITICAL) | Yes (configurable)        |
| SBOM             | Yes                       |
| Sign Image       | Yes                       |
| Push to ECR      | Yes                       |
| Deploy           | Yes                       |
| Verify           | Yes — rejects deployment  |

---

## Least Privilege Principles

- Jenkins IAM user: ECR-only permissions
- Deployment SSH user: docker group only (no sudo)
- Container: non-root user, no unnecessary ports
- ECR: immutable tags prevent tag overwrite attacks
- Pipeline: `disableConcurrentBuilds()` prevents race conditions
